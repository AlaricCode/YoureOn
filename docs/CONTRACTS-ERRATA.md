## [verdict-rules] decoder/evaluator decisions (crates/verdict-rules)

The TS engine MUST mirror these choices (they are where §5.1's rejection list and §2.7/§3 leave room):

1. **program_bin validation beyond §5.1's explicit list.** `MalformedProgram` is also returned for these §2.7 rules, because the evaluator needs them to be well defined or to stay secure:
   - `ACTOR_BOUND_MISMATCH`: leg flag bit0 ≠ (va or success references a `person` entity). Otherwise a leg could skip identity checkpoints.
   - `NEGATIVE_ACTOR_RULE`: an actor-bound `never`; an actor-bound `count` whose cmp ∉ {`>=`, `>`}; an actor-bound `count >= 0`. §3.8's anchors (`k'`) are undefined for these rules.
   - `BAD_RULE`: has_valid_attempt ⇔ (`count` with `rule_n > 0`); `holds`/`before` need `1 ≤ rule_n ≤ min(36000, LIMIT)`; count `k ≤ REPS_MAX`; attempts `≤ ATTEMPTS_MAX` (20), or `≤ 8` when actor-bound.
   - Unused rule fields must be 0. `exists`/`never`: cmp = k = n = 0. `holds`/`before`: cmp = k = 0. Rules legs need `attempt_window ∈ 1..=36000`.
   - Market legs: flags = 0, cmp = 0, `k ∈ {0,1}`, n = 0, `attempt_window = 0`, va_len = 0, succ_len = 32. Rules programs cannot have `rule_kind 5`, and market programs can only have it.
   - Counts: rules/market need L ≥ 1 and ai_judged needs L = 0. An ai_judged condition is exactly `[0x51]`.
   - Header ranges: P ∈ 2..=8; each stake in `[MIN_STAKE_UNITS, MAX_STAKE_UNITS]`; rules/ai_judged stakes all equal; time_limit_s is `1..=3600` (market: `..=2592000`); `if_true`, `else` ∈ {0,1} and differ.
   - **Not** enforced by the decoder: `CHECKPOINT_LIMIT` (§0.6 requires a vector with more than 8 checkpoints, so §3.8's guard must be reachable), participant distinctness, `MAX_PARLAY_LEGS`, `UNUSED_PERSON`.
2. **Calibration presence.** Rules programs need a VCAL blob, even when R = 0. An empty blob for a rules program is `MalformedCalibration`. ai_judged and market programs need an empty calibration_bin; a non-empty one is `MalformedCalibration`.
3. **Third part by kind.** Market programs decode the third part as `market_bin` (a VTRK blob there is `MalformedTracks`). Rules and ai_judged programs decode it as `track_bin`. For ai_judged, T must be 0 and any valid flags are accepted. Decode order is program → calibration → tracks, and the first error wins.
4. **`holds(D)` without full coverage.** The raw value is **False**: a missing frame counts as not satisfied, so no checkpoint is produced. The cause is COVERAGE. `decisive_frames` is the first frame **in F** that is < D and has !S.
5. **`leg_causes`.** Each per-leg list has at most one entry, the first applicable cause (§3.9). Market VOID uses `["VOID"]`.
6. **Rust padding.** `EvalOutput.checkpoints` entries past `n_checkpoints` are `(0, 0)`. `leg_results` past L are `0xFF`. If |F| > 64·W (only possible when a caller picks W < 16), the result is needs_panel reason 13, the same as the cost cap.

## lang (engine rule language, §2)

- **lang-1 (reserved words vs §15.1).** §2.2/§2.5.4 forbid reserved words as entity names, but the worked example §15.1 declares `line: region(tap)` and writes `shooter behind line` (`line` is reserved). Resolution: the reserved words `tap line zone any opening interior` never occur as standalone tokens in the expression/rule/outcome grammars (only inside entity values or as a `.opening`/`.interior` suffix), so they are accepted as entity names and lexed as plain identifiers. All other reserved words remain keywords and are rejected as entity names (`PARSE_ERROR`).
- **lang-2 (UNUSED_PERSON on canonical programs).** The canonical AST resolves `side(<person>)` to 0/1, so `validateProgram(p, ctx)` on a canonical program cannot know whether an otherwise unused `person` entity was named in the outcome. `UNUSED_PERSON` is therefore enforced by `parseYaml` (which passes the side references through) and skipped by a bare `validateProgram`. `toYaml` writes `side(<person>)` for such entities so that `parseYaml(toYaml(p))` round-trips.
- **lang-3 (unassigned codes).** Codes the contract does not assign are chosen as: participant count outside 2..8, entity count > 16, leg id outside 1..8 or not strictly ascending → `LIMIT`; duplicate participant or participants[0] ≠ creator → `UNKNOWN_PARTICIPANT`; bad entity name/phrase, unknown YAML keys, `version ≠ 2` → `PARSE_ERROR`; rules program without entities/legs, ai_judged with legs or without question, market leg with `attempt_window_s` → `BAD_KIND`; question length → `LIMIT`; `wins iff yes` outside ai_judged (or its absence in ai_judged) → `BAD_OUTCOME`; missing `stake_each`/`stakes` → `BAD_STAKE`; market YAML without `time_limit_s` → `BAD_TIME_LIMIT`; holds/before duration 0 → `BAD_RULE`; a `count` k/N range error → `BAD_RULE` (actor-bound N > 8 → `CHECKPOINT_LIMIT`).
- **lang-4 (`canonicalize` ctx).** §4.2 calls `canonicalize(program)` without a context; `canonicalize(p, ctx?)` therefore takes an optional context, which is only needed to resolve `person(...)` forms and the `participants` default of a draft.
- **lang-5 (read-back details).** Unspecified read-back choices: `person(any)` renders as `labels[name]` or "someone"; children of `not`/`for_duration`/`before` that are binary ops (`and`/`or`/`then_within`) are wrapped in "(…)" like and/or children; side names are joined "A, B and C"; conditions render `not (…)` around non-leg operands. `conditionRows` uses the leg **id** as `leg`.
- **lang-6 (compileMarket).** `time_limit_s` uses the latest `close_time_ms` across parlay picks. Parlay probability multiplies the unclamped side probabilities and clamps once at the end (§11.3 "then clamp"); a single leg is clamped as in §11.2.

- **Engine encode: decoder checks beyond the §5.1/§5.3/§5.4 bullet lists (Rust decoders should match).** To keep one valid form per AST, `decodeProgram` additionally rejects with `MalformedProgram`: duplicate participant pubkeys; any stake outside `[MIN_STAKE_UNITS, MAX_STAKE_UNITS]`; unequal stakes for rules/ai_judged; `time_limit_s` outside `1..=3600` (market `1..=2592000`); `L = 0` for rules/market and `L ≠ 0` for ai_judged; rules leg `attempt_window` outside `1..=36000`; leg `actor_bound` flag ≠ "references a `person` entity (a or b, va or success)"; `has_valid_attempt` ≠ (`va_len > 0`) and ≠ (`rule_kind = count ∧ rule_n > 0`); count `k > 1000`, `attempts > 20` (`> 8` for actor-bound legs, §0.5); holds/before `rule_n` outside `1..=time_limit_s·FPS`; unused rule fields ≠ 0; market legs with flags ≠ 0, `rule_k > 1`, `attempt_window ≠ 0`, `va_len ≠ 0` or `succ_len ≠ 32`; a rules leg (`rule_kind 0..4`) in a market program or a market leg in a rules program. Not enforced by decoders (compile-time only): `NEGATIVE_ACTOR_RULE`, `CHECKPOINT_LIMIT` static bound / `k' ≤ 8`, `UNUSED_PERSON`, `BAD_OUTCOME` "every leg must be used" (none is required) — the "more than 8 checkpoints" vector needs these to stay decodable.
- **Engine encode: track_bin details.** `id_conf ≠ 0` is rejected on every non-`person` track (incl. `person_any`); `pose` is allowed on `person` and `person_any`, rejected on `object`. For ai_judged the decoder requires `S = 0` (T is 0 by [D-43]) but does not force `flags = 0b10` (bits 0–4 free). `decodeTrackBin` on a market program ⇒ `MalformedTracks`. A record with `conf = 0` and all-zero fields decodes as `null`.
- **Engine encode: hash return types.** `jsonHash`, `programHash`, `sceneHash`, `calibrationHash`, `marketHash`, `modelHash`, `bioHash`, `termsHash` return lowercase hex (`Hex32`, matching the Bet/DecodedProgram fields); `sha256`, `acceptSigMessage`, `acceptanceAudioHash` return `Uint8Array` (§14). `*Bytes` variants exist for json/scene/market hashes. `jsonHash(p)` assumes `p` is already canonical (`canonicalize` needs the compile context). Leaves for `acceptanceAudioHash` are built with `acceptanceCreatorLeaf(wav|null)` and `acceptanceLeaf(wav, sig)`. Decoder errors are thrown as `EngineError` (`.code` = §9.6 name), exported from the engine root.

## evidence-identity (engine §7, §8)

- **ei-1 (beacon synth, §7.5).** The engine uses the App envelope above (`env(n) = env(2399 − n)`, endpoints 0) and rounds `32767·s` **half away from zero** (Dart `round()`), with the same float evaluation order as the app, so 48 kHz PCM is bit-identical. Non-48 kHz synthesis (tests only) uses `N = round(rate·0.05)`, `R = round(rate·240/48000)`.
- **ei-2 (beacon decode, §7.5).** Decoder details the contract leaves open: inputs below 11.5 kHz return null; 11.5–16 kHz are upsampled to 16 kHz, above 48 kHz downsampled to 48 kHz. Preamble alignments are ranked by the expected-tone energy **divided by the total 16-tone energy** of the six preamble windows (raw energy lets loud broadband noise win), and the best 8 alignments ≥ 25 ms apart are tried until one passes the CRC. After CRC success the alignment is refined to ±1 sample using the energy of all 42 decoded tones; `t0Sample` is in the caller's sample rate.
- **ei-3 (fusion presence, §8.5).** A person-track frame is "present" iff its record is non-null and `conf > 0`. Face observations on a track that is not present at the observation frame (or unknown track ids) are dropped; observations outside `[0, n_frames)` are ignored; scores for candidates `≥ M` are ignored. "Last present frame" in re-ID inheritance is the from-track's global last present frame. Voice observations ignore any `track_id` (target per §8.5 only). A face observation with no scores is ignored (no 0.7 decay).
- **ei-4 (voice segments for the prover, §8.6).** `IdObservation` has no segment bounds, but prover rule 2 needs "segment covers frame". The engine accepts optional `start_frame`/`end_frame` (inclusive) on voice observations (`SegmentedIdObservation`); without them the segment is `[frame, frame]`. Among several qualifying observations: faces → latest `g`, then highest `cos_bps(p)`; voices → highest `cos1`.
- **ei-5 (prover circuit check, §8.6).** `proverInput` cannot evaluate `circuitMatch` from scores alone (cos_bps uses a floored isqrt and can exceed the exact cosine). It takes an optional 4th argument `{circuitCheck(obs, tau)}`; the backend MUST pass one that runs `circuitMatch(enrolled_p, observed, tau)`. Voice proofs use `tau = TAU_VOICE_BPS`.
- **ei-6 (audio cross-check window, §7.6).** "±500 ms of a decisive frame" is measured from the frame's interval: a tag at `at_ms` (session time) matches frame f iff `f·100 − 500 ≤ at_ms < f·100 + 100 + 500`. Impact tags are Scribe event types matching `/impact|thud|clap/i`. `audio_disagree` is set if any audio witness has an impact tag and at least one `disappears_into`/`touches` decisive event has no matching tag on any witness.
- **ei-7 (quantizeEmbedding, §8.2).** Inputs within 1e-6 of unit L2 norm are quantized as given; other inputs are normalized first (zero vector → zeros). `cosineBps`/`circuitMatch` zero-extend vectors of different length (128-d face ≡ its 192-d padding).

## [engine/eval] §3 evaluation — interpretation notes
- **holds raw value with missing coverage (§3.7/§3.8).** When some frame of `[0, D)` is not in F, the leg is Unknown (COVERAGE), but §3.8 still needs a raw value for checkpoints. The TS evaluator uses `raw = ∀ f ∈ F ∩ [0, D): S[f]` (vacuously True), so an actor-bound holds leg with missing coverage still emits its checkpoint `(p, D-1)`. Rust should match (affects `checkpoints`/`n_checkpoints` only; the leg is Unknown either way).
- **count-with-attempts decisive frames (§3.7).** `DF` = all `a_i` and defined `s_i`, emitted ascending and deduplicated (`s_i == a_i` is possible). Attempts end at `min(a_i + W, next rising(V) frame in F_R)`; `s_i` is searched only in `seg(a_i) ∩ F_R`.
- **Anchors for actor-bound legs with non-positive rules (§3.8).** Validation forbids them; as a guard the evaluator uses `k' = k` for cmp ∉ {`>=`, `>`} and takes the first `min(k', available)` anchors; an actor-bound `never` leg yields no checkpoints.
- **evaluateSession (§14).** A full session can exceed `MAX_EVAL_FRAMES` (1024), which `decodeTrackBin` enforces, so `evaluateSession` encodes+decodes program and calibration but passes the single-segment buffer (frames `[0, min(n_frames, LIMIT+TAIL_FRAMES))`, tracks = `tracked_entities`) to the same decoded-input evaluator with `maxCost = ∞`. `evaluateProgram` is strictly `encode*` + `evaluate`.
- **leafSignals (§14, §12.10).** Implemented in `src/eval/leafSignals.ts` (the `lang` module header also lists it — only one module may export it from the package root). Rows: `leg` = leg **id**; `path` = child indices joined by "." with `""` for a root leaf; signals over the session as one segment from frame 0; unplaced regions (or `c = null`) ⇒ all-false. Entity label = calibration `entity_refs[].label`, else the object phrase, else `line`/`zone`, else the entity name.

## [engine/perception] §6.2 / §6.3 / §6.5 / §13
- **§6.5 window brackets.** The table's `[a, b]` windows are read as inclusive (`[k-20, k+20]` = 41 frames); `[0, D)` is half-open. ## App (Flutter, part 2: Huddle → Receipt, Pay, World)
- **App: camera pose convention (§5.2 `pose`).** The axes are not defined. The app derives the pose from the accelerometer (device axes x right, y up, z out of the screen): `pitch_cdeg = round(atan2(z, √(x²+y²))·18000/π)` (0 = screen vertical) and `roll_cdeg = round(atan2(x, y)·18000/π)` (0 = upright portrait). Drift = max(|Δpitch|, |Δroll| wrapped to ±180°). "Camera moved" shows when drift > `CAMERA_POSE_DRIFT_CDEG`. The pose is advisory and only the app compares it.
- **App: scene capture geometry.** Scene check and Record lock the camera phone to portrait. Calibration `camera` is the upright capture size, for example `720×1280 portrait` for `ResolutionPreset.high`. The same values are sent as `width_px`/`height_px`/`orientation` on camera chunk records. Scene frames are upright JPEGs, so the backend should evaluate them in that frame.
- **App: `DraftView.frozen`.** §12.3 says a PATCH clears acceptances, and also that acceptance "freezes the draft". The app reads `frozen = true` as read-only. Dictate, Who, Stake, Limit and the question chips are disabled once anyone has accepted, and What (read-back) stays viewable.
- **App: counterparties following the creator (contract change: `DraftView.bet_id`).** `BetView` has no `draft_id`/`huddle_id`, and the `bet` view is only pushed to `bet:<id>` subscribers, which no other phone is yet. Only `huddle:<id>` reaches every member (bystanders included), so `DraftView` gains optional `bet_id` (the Bet PDA), set once the draft's `create_bet` confirms; the existing confirm handler republishes the draft on `huddle:<id>`, and the huddle snapshot covers late subscribers. Every non-creator Terms screen (counterparty or bystander) that sees `bet_id` (live, or already on load) fetches `GET /bets/:id`, checks `program_hash == draft.program_hash` and opens Scene check (or Ruling for market bets). A `notify` naming a `bet_id` is a backup for participants and also makes Home upsert that bet.
- **App: late `start` (contract change: `start` replay).** `start` used to be a one-shot publish. While a bet is Live, the `bet:<id>` snapshot now also replays the stored `start` (built exactly like `publishStart`), so a phone that reconnects or opens Record after the start still begins. The app treats `start` idempotently. A phone that begins late resumes only witnesses it registered before the list froze (re-registering the same key is idempotent), does not play the start signal, and uses the bet's `t0_ms` for its clock. It never hears the beacon, so its footage stays unsynced unless another witness on the same device heard it. A phone whose registration did not succeed before the start shows "Not a witness" and records nothing; `WRONG_STATE` on register is no longer treated as success.
- **App: notifications ([D-29]).** WS `notify` titles are an in-app banner in the foreground and local notifications (`flutter_local_notifications`) in the background. iOS and Android Doze suspend the socket soon after backgrounding, so the app also (a) schedules a local "Consent due" notification `2 min` before a pending pre-ruling consent deadline (inexact, no exact-alarm permission), and (b) on resume re-fetches bets and shows changed ones as banners. No backend change.
- **App: capture screens and app lifecycle.** Huddle, Scene check and Record keep the screen on (`wakelock_plus`). Huddle closes its back camera and detector before pushing Terms and reopens it on Back. Scene check closes its camera (awaited) before replacing itself with Record, and Record retries `open()` once. On pause/hidden the camera screens release the camera and reopen it on resume. If Record is paused while recording, it finalizes this phone's witnesses through the normal end path (tail, final chunks); the camera is never restarted mid-recording. Leaving Record mid-recording keeps the camera controller open until the witnesses have finalized. A camera witness whose controller fails seals what it could cut as its `final` chunk, or posts an empty `final` chunk, so the backend sees a clean end (a gap) and not a missing final. Audio-only witnesses still need the app in the foreground: there is no Android foreground service.
- **App: server-built URLs.** The backend builds absolute URLs from `PUBLIC_URL` (default `http://127.0.0.1:<port>`). The app rebases every absolute URL whose path starts with `/v1/` onto its configured API origin (`ApiTransport.resolve`), so `upload_url`, `audio_url`, `wav_url`, `sfx_url` and `yaml_url` work on devices and emulators, and the bearer token only goes to that origin. Other absolute URLs (explorer links) are kept.
- **App: Receipt "Rules file".** `yaml_url` is an authenticated API route, so the app fetches it in-app with the session and shows it in a sheet. Only non-API absolute URLs (explorer and tx links) open in the external browser.
- **App: audio session.** The camera phone records its audio witness while it plays the start sound and beacon. Recorders use `AudioInterruptionMode.none`, and the global `audioplayers` context is iOS `playAndRecord` (`defaultToSpeaker`, `mixWithOthers`) with Android `AudioFocus.none`, set at app start. This needs on-device verification that the beacon is recorded on the same device.
- **App: wallet signing.** `message_b64` is signed only if it parses as a legacy/v0 Solana message header whose required signers include the wallet key, with room for the keys and blockhash, and not starting with `VERDICT/`. Otherwise the result is `TX_FAILED` and no prompt is shown. The prompt reason is the `summary`. Stake, pay, dispute bond and World bets always prompt (`fresh`), and signing in does not open the 60 s unlock window. Cleartext HTTP is allowed in debug/profile Android builds only.
- **App: World retry.** Quotes are single-use (bwe-7). A `TX_EXPIRED` re-request first re-quotes the same legs and total, and creates a new bet only if the split and odds are unchanged. Otherwise it shows the new price ("Price changed") and the user taps Propose again. With no counterparty candidates, World shows "No counterparty" with a Huddle way forward.
- **App: offline launch.** With a stored token and a non-`UNAUTHORIZED` failure of `GET /me`, the app shows an "Offline" screen (Retry, "Sign in instead") and retries `GET /me` with backoff of 1, 2, 4 … 30 s. `UNAUTHORIZED` clears the session.
- **App: "Delete biometrics"** needs a second tap ("Confirm delete") within 3 s.
- **App: joining a huddle.** §12.13 Home has no Join entry. The Huddle screen creates a huddle on open, and its "Join" chip takes a 6-digit code (`POST /huddles/join`). A user who joins someone else's huddle leaves their own empty huddle behind, so the backend should tolerate empty huddles.
- **App: World counterparty set.** No route lists "confirmed recent huddle members". From Huddle or Terms the app uses that huddle's confirmed members (excluding the caller). Otherwise it uses the other participants of the caller's bets. A dedicated route (the §8.3 pay set) would be better.
- **App: Agent mode.** `POST /agent/session` is called once per Terms screen. Both modes then use record-and-compile (`POST /bets/compile` with `audio_b64`), because no ElevenLabs conversational SDK is wired into the app. In `elevenlabs` mode the backend's tool webhook remains the Agent path.
- **App: question UI.** Question text is never displayed; it is spoken via `audio_url`, with a replay control. `choice` answers on chip tap. `multi` answers with the chosen chips joined by ", " (chip order) after "Done". `free` uses a text field.

## [engine-integration] TS ↔ Rust alignment, golden vectors, gen:dart

- **ei-int-1 (holds without full coverage; supersedes the "[engine/eval] holds raw value" note).** The TS evaluator now follows "[verdict-rules] 4": a frame of `[0, D)` missing from F counts as not satisfied, so the raw value is **False**, no checkpoint is produced for an actor-bound `holds` leg, and the cause is COVERAGE. `decisive_frames` = the first frame in `F ∩ [0, D)` with `!S` (none if every present frame holds).
- **ei-int-2 (program_bin decoder; supersedes part of "Engine encode: decoder checks").** The TS decoder now rejects `NEGATIVE_ACTOR_RULE` programs with `MalformedProgram` (actor-bound `never`; actor-bound `count` unless `>= k` with k ≥ 1 or `> k`), as crates/verdict-rules does. Participant **distinctness is not a decoder check** in either implementation (it is a §2.4 / `validateProgram` rule and an onchain `create_bet` check). `CHECKPOINT_LIMIT` stays compile-time only.
- **ei-int-3 (ai_judged track_bin segments).** §5.4 lists "S = 0 unless bit3 is set or the program is ai_judged" and "S ≠ 0 when bit3 is set" as the only S rules. Both decoders therefore accept an ai_judged track_bin with `T = 0` and `S > 0` (the result is reason 11 regardless) and reject `S > 0` with bit3. Encoders still emit the §5.6 minimal form (`T = 0, S = 0, flags = 0b10`).
- **ei-int-4 (exhibit chain proofs, §10.1).** §10.1 says `c_{from-1}` "is included as the prev of the first link", but the `links[]` shape has no such field. The engine's `ChainLink` has an optional `prev` (hex), present only on the first link and only when `from_index > 0`; with `from_index = 0` the chain starts at `G_w` (the verifier needs the bet/beacon inputs). `verifyExhibitChainProof(proof, {witness_key, evidence_root, genesis?, n_witnesses?})` recomputes `c_from … c_head`, checks `leaf_w` against `head_proof.leaf`, then `head_proof` against the root. Backend exhibits SHOULD carry `links[0].prev` when `from_index > 0`.
- **ei-int-5 (golden vector files, §0.6).** `npm run vectors` writes `testvectors/<name>.json` (237 vectors), `testvectors/index.json` (manifest, no `expected`; lists names, descriptions and §0.6 coverage tags) and `testvectors/fuzz.jsonl` (2048 cases, seed 1). Format details beyond §0.6: market vectors carry their third part as `market_bin`; fuzz lines always use `track_bin` for the third part (a market_bin for market programs) and `verified`; `opts.maxCost: null` means ∞ (absent = `MAX_EVAL_COST`); decoder-rejection vectors contain only the binaries and `expected.error`; extra informational fields (`description`, `covers`, `compile_errors` for decodable-but-invalid programs such as the > 8 checkpoints case, `fusion` inputs of the identity-conflict vector, `expected.attempts`, `expected.cost`) are TS-only and not compared by Rust. All 237 vectors and 2048 fuzz cases pass `cargo test -p verdict-rules --test vectors` with `VERDICT_STRICT=1` (leg_causes compared too).
- **ei-int-6 (`npm run gen:dart`).** Implemented as `packages/engine/scripts/gen-dart.ts`: renders `app/lib/contracts/constants.dart` from `GLOBAL_CONSTANTS` (doc comments from the JSDoc in `src/constants.ts`); `--check` compares declared names/values only (formatting-insensitive). The current hand-written App file passes `--check`; it was not overwritten.
- **ei-int-7 (World Mode math).** `compileMarket` now uses `world/stakeSplit` and `world/parlayProb` (single implementation of §11.2/§11.3); a split outside `[MIN_STAKE_UNITS, MAX_STAKE_UNITS]` is `BAD_STAKE`.

## [anchor] programs/verdict — implementation notes and contract issues

1. **§3.13 compute budget — RESOLVED (D-47, see [compute-budget] below).** Originally: with `MAX_EVAL_COST = 16384` and `overflow-checks = true`, cap-level programs needed 3–11M CU (≈175–690 CU per cost unit; `moving` ≈ 1,350 CU/frame, mostly checked u64/i64 multiplication lowered to `__multi3` calls), so the `worst_case_*` benchmarks were `#[ignore]`d. Now the interpreter is optimized, `MAX_EVAL_COST = 8192`, `cost = (|F| + EVAL_COST_SETUP_FRAMES) × Σw` and the polygon leaves are reweighted; every accepted buffer is bounded at ≤ 1.08M CU and the `worst_case_*` benchmarks run (un-ignored) at ≤ 542K CU.
2. **Bet account type.** It follows §9.3/§9.1: Borsh `#[account] Bet` used as `Box<Account<'info, Bet>>`, space 8 + 1580. The orchestrator task asked for a "zero_copy Bet", but the contract says Borsh. The byte layout is the same either way (packed, LE, no padding), and `tests/kinds.rs` spot-checks offsets. `TrackBuffer` is `#[account(zero_copy)]` (48 B header, discriminator `account:TrackBuffer`) and appears in the IDL.
3. **Error codes where §9.4 names none:** `display_name` > 32 bytes → `BadCommitment`. Witness list with a duplicate key, kind > 2 or the default key → `TooManyWitnesses`. Market `start` with `beacon_slot ≠ 0` → `BeaconSlotNotFound`, and with witnesses → `TooManyWitnesses`. `fund` `program_hash` mismatch → `ConsentMismatch` (the same as `terms_hash`). Rules `fund` with a zero calibration hash → `CalibrationMismatch`. `create_bet` zero `program_hash` → `ProgramHashMismatch`. Oracle listed as a participant → `BadParticipants`. Default (all-zero) judge key → `BadJudges`. `verify_biometric_proof` modality > 1 → `BadReason`. `consent` by a non-participant before the deadline → `DeadlineNotReached` (chainmodel decision). `run_rules`/`verify_sp1_run` after `ended_at + PERCEPTION_TIMEOUT_S` → `DeadlinePassed` (§9.4 #9 [D-36]). `settle_panel` after `disputed_at + PANEL_TIMEOUT_S` → `DeadlinePassed` (§9.9; refund reason 6 instead). `dispute` with `evidence_root ≠ bet.evidence_root` → `ConsentMismatch`. Beacon slot greater than the current slot → `BeaconSlotNotFound`.
4. **Anchor account validation runs before handler checks.** `run_rules` with no TrackBuffer at all fails with Anchor 3012 (AccountNotInitialized), not `TracksNotFinalized`. Any instruction on a terminal bet whose vault is already closed (refund/consent/cancel after settlement) fails with 3012, not `InvalidState`/`NotRefundable`.
5. **Payout accounts** (remaining accounts) are validated only when funds actually move. A `consent` that only sets a bit may omit them. Each payout account must be writable, owned by the token program, `mint == bet.mint` and `owner == participants[i]` (`BadTokenAccount`), and an account is required even when its payout is 0.
6. **Terminal bookkeeping:** refunds (including the panel's no-contest) set `settle_path = 4` (REFUND), `refund_reason` and `settled_at`. `settle_panel` outcome 0 → Refunded, reason 2. `Settled.pot` = Σ funded stakes + upheld bond (dust excluded; dust is included in `payouts[i]`).
7. **`post_tracks`:** `TracksPosted` is emitted only on `finalize`. Write order: layout, lengths and offset checks, then on finalize: program hash → calibration hash (empty ⇔ zero) → decode program → decode calibration → program/bet match (`ProgramBetMismatch`) → tracks decode. Without feature `sp1`, an empty tracks part → `BufferLayout`. The engine vector `reject_tracks_empty` expects `MalformedTracks` from the pure decoder; onchain, §9.4 #8 takes precedence. A pre-funded TrackBuffer PDA (lamports sent before creation) is handled with transfer + allocate + assign instead of `create_account`.
8. **`end`:** with empty heads, the final root = the root of the stored heads; `seq` is ignored and gap bits are unchanged. `EvidenceCommitted{is_final: true}.seq` = the stored `evidence_seq`. "All bits" in the 90 s gap rule = the bits of the registered witnesses only.
9. **Panel (§9.7):** "exactly one Ed25519 instruction" is enforced by scanning every instruction in the transaction. Structural problems → `BadEd25519Instruction`. Duplicate or non-judge keys → `InsufficientQuorum`. Signature validity is left to the precompile, which LiteSVM enforces (a forged signature fails the transaction).
10. **`verify_sp1_run` (feature `sp1`, off by default):** the public values (171 bytes) are fully checked against the Bet, and the ruling is applied as in `run_rules`. No SP1 Groth16 verifying key is wired, so proof verification is **fail-closed** (`BadProof`), except for the `mock-zk` test proof (a `proof` starting with 64 × 0x01). Settlement of such a pre-ruling uses path RULE (`tracks_finalized == 2`). After the proof check the ruling must be self-consistent, mirroring the TS model, else `BadProof`: WINNER ⇒ `reason == 0`, `winner_mask ≠ 0` and within the participants; otherwise `preruling == NEEDS_PANEL`, `reason ∈ 10..=13`, `winner_mask == 0`; every `leg_results[i] ∈ {0,1,2,0xFF}`. (No side-membership check on a WINNER mask: the model has none either.) Also `DeadlinePassed` after `ended_at + PERCEPTION_TIMEOUT_S`. Covered by `programs/verdict/tests/sp1.rs` (features `sp1,mock-zk`, program built into `target/deploy-sp1`). The SP1 path itself is dropped for this build, see [sp1-dropped].
11. **ZK:** `programs/verdict/src/zk/vk.rs` is a copy of `circuits/build/vk.rs` (converter: `circuits/scripts/vk-to-rust.ts`), so no `scripts/vk_to_rs.*` was added. The LiteSVM tests verify a **real** Groth16 proof: `programs/verdict/tests/fixtures/biometric_proof.json`, regenerated by `gen_biometric_fixture.mjs` for the deterministic test bet. `verify_biometric_proof` with a real proof takes 132K CU. `mock-zk` tests need a separate build: `cargo build-sbf --manifest-path programs/verdict/Cargo.toml --features mock-zk --sbf-out-dir target/deploy-mock-zk`, then `cargo test -p verdict --features mock-zk`.
12. **Toolchain / lockfile:** the program ID is `dbqDmF6YtjPygXTvJD31CNADoLqiUG8pZgj1zpHaMye` (the keypair is in `target/deploy/`, uncommitted). The program crates resolve to the solana 2.x component crates (anchor-lang =0.32.1, litesvm 0.7.1, groth16-solana 0.2.0, with a single `solana-pubkey`/`solana-instruction` version). Run future `cargo update`s with that env var, or edition-2024 crates (e.g. `zeroize_derive 1.5`) will break `cargo build-sbf`.

## [backend scaffold] §12 / §13 decisions (packages/backend)

- **backend-1 (HTTP status per §12.8 code).** The contract fixes only 409 (`CALIBRATION_LOCKED`) and 413 (`CHUNK_TOO_LARGE`). Chosen: UNAUTHORIZED 401, NOT_FOUND 404, WRONG_STATE 409, NOT_ENROLLED 403, LIVENESS_FAILED/FACE_NOT_MATCHED/VOICE_NOT_MATCHED/PHRASE_NOT_HEARD 422, CODE_INVALID 404, HUDDLE_FULL 409, DRAFT_INVALID 422, NOT_ACCEPTED 409, CHALLENGE_EXPIRED 410, INTERNAL 500, CALIBRATION_INCOMPLETE/CAMERA_MISMATCH/NO_CAMERA 422, INSUFFICIENT_FUNDS 402, TX_EXPIRED 410, TX_FAILED 422, QUOTE_EXPIRED 410, BAD_STAKE 422, RATE_LIMITED 429, WALLET_MISMATCH 403, SPEND_DISABLED 403 (`packages/backend/src/errors.ts`). The App keys on `error.code`, not the status.
- **backend-2 (malformed requests).** §12.8 has no "bad request" code. Malformed JSON / missing fields answer HTTP **400** with code `WRONG_STATE` ("Not available"). Unimplemented scaffold routes answer **501** with `INTERNAL`.
- **backend-3 (`POST /tx/:id/submit` errors).** Request-level problems are HTTP errors: unknown tx or another user's tx → 404 `NOT_FOUND`; past `expires_at_ms` or blockhash expired → 410 `TX_EXPIRED` (the app re-requests once); a user signature that does not verify over `message_b64` → 422 `TX_FAILED`. On-chain execution failures are HTTP 200 `{status:"failed", signature, error:{code: TX_FAILED | INSUFFICIENT_FUNDS, message}}`. Re-submitting a settled tx returns the stored result (idempotent).
- **backend-4 (generated secrets).** §13 lists `JUDGE_KEY_0..2`, `ORACLE_KEY`, `FEE_PAYER_KEY` as generated into `.env`. The backend also generates `BIOMETRIC_KEY` (needed for AES-256-GCM at rest) and `ELEVENLABS_TOOL_SECRET`; it never generates `ORACLE_KEY` (so it defaults to `FEE_PAYER_KEY`) or `QUICKNODE_SECRET` (comes from QuickNode). `.env` lives at the repo root (override with `VERDICT_ENV_FILE`), mode 0600; process-env values win over the file.
- **backend-5 (extra env vars, not in the §13 table).** `PORT` (8787), `HOST`, `PUBLIC_URL`, `LOG_LEVEL`, `SOLANA_RPC_URL` (devnet default), `SOLANA_WS_URL`, `PERCEPTION_URL`, `EMBEDDER_URL`, `DETECTOR_URL`, `GEMINI_HEDGE` (`mock|live`; `live` is the §11.6 paid hedge and is spend-guarded), and provider credentials `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_API_KEY` (LLM "gemini" — distinct from the Gemini exchange), `XAI_API_KEY`, `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID`, `NOSANA_API_KEY`, `SP1_PRIVATE_KEY`. `ALLOW_SPEND` accepts only unset/empty or `1`; any other value is a startup error (never an implicit yes). `SOLANA_MODE=mock` requires `CHAIN_EVENTS_SOURCE=mock`; `quicknode` requires `QUICKNODE_SECRET`.
- **backend-6 (video-capable judges).** "J0 must be video-capable" (§13/§10.3) is enforced at startup with the set `{mock, gemini}`.
- **backend-7 (mock chain clock/slots).** `slot = 1_000_000 + floor((now_ms − genesis_ms)/400)`; slot hash = `sha256("mock-slot" ‖ u64 LE slot)` (§13), blockhash = base58 of the current slot's hash, valid for 150 slots. SlotHashes (≤ 512, newest first) holds the slots *before* the current one, including pre-genesis slots, so a beacon is always available (`latestSlotHash` = current − 1). Mock USDC mint (unless `USDC_MINT`) = `base58(sha256("verdict/mock-usdc-mint"))`; the faucet credits the owner's ATA directly. The mock chain also checks Anchor-style seeds (Bet/vault/profile/track_buffer PDAs) that `chainModel` leaves to the program, and executes SPL Token `Transfer`/`TransferChecked`/`MintTo`, ATA `Create[Idempotent]`, ComputeBudget (no-op) and the Ed25519 precompile (panel layout only). Groth16 is accepted unless a verifier is injected. With PROVER=snarkjs the prover pre-verifies every proof (`groth16.verify` against `circuits/build/verification_key.json`) and caches it, and its synchronous `verifier` (the mock chain's `verifyGroth16`) accepts exactly the cached (public inputs, proof) pairs (see backend-audit-prover).

- **backend-9 (mock identity subject).** The §13 mock embedder needs to know whose face/voice the bytes depict; providers take `{subject_user_id}` (the caller for enroll/accept/pay-voice, the next not-yet-confirmed member for huddle scans). Without a subject the embedding belongs to an unknown person and matches nobody.
- **backend-10 (email login).** No email provider is listed in §13, so `POST /auth/email/start` always issues the mock code `000000` (5 wrong attempts ⇒ `RATE_LIMITED`). ### identity-huddle (backend service: identity, huddles, drafts, acceptance, create_bet)
- **identity-huddle-1 (mock subject header).** Refines backend-9: in mock identity mode only, the `x-mock-subject: <user_id>` header overrides the default subject (enroll/accept → caller; pay scan/voice → first closed-set candidate; huddle scan → next unconfirmed joined member). Real providers ignore subjects and the header.
- **identity-huddle-2 (liveness without a pose model).** `POST /enroll/face` and `/pay/scan` liveness = every frame is a JPEG (SOI…EOI, ≤ 2 MiB), frames are pairwise distinct (replayed stills fail), and each prompted frame's quantized embedding has `cos_bps ≥ TAU_FACE_BPS` against the neutral frame. Head-pose verification of the prompt direction is not implemented. Enrollment failure is `LIVENESS_FAILED` (422); pay scan returns `liveness: false` and all `matched: false`.
- **identity-huddle-3 (voice enrollment).** Each clip's transcript must contain its phrase (normalized as §12.3 accept); clip length 0.3–30 s else `PHRASE_NOT_HEARD`; the three clips must each be within `TAU_VOICE_BPS` of their mean, else `VOICE_NOT_MATCHED`. `POST /enroll/complete` seals whatever modalities are pending (a missing one keeps its earlier template, or a zero commitment); `enrolled.*` flips on at complete, not at `init_profile` confirmation.
- **identity-huddle-4 (bad accept_sig).** §12.8 has no code for an invalid `accept_sig`; it is HTTP 400 `WRONG_STATE` (same convention as backend malformed requests). Order of checks in `POST /drafts/:id/accept`: challenge (`CHALLENGE_EXPIRED` also when the program_hash changed since issue) → WAV → accept_sig → transcript/diarization (`PHRASE_NOT_HEARD`) → voiceprint on the chosen speaker's audio only (`VOICE_NOT_MATCHED`). Only counterparties (participant index ≥ 1) accept; the creator is shown `accepted: true`.
- **identity-huddle-5 (question audio route).** `Question.audio_url` needs a URL; added `GET /v1/drafts/:id/questions/:qid/audio` (TTS of the question text, auth like readback.mp3). Audio responses carry the provider's real MIME (`audio/wav` from the mock TTS even on `readback.mp3`).
- **identity-huddle-6 (huddle rules).** Codes are valid for `RECENT_HUDDLE_S` after creation (`CODE_INVALID` afterwards); only the creator scans (D-22); the creator removes others, members remove themselves, the creator cannot be removed; non-members get `NOT_FOUND`; unconfirmed members cannot compile (`WRONG_STATE`). Pay closed set = confirmed members of huddles *created* within `RECENT_HUDDLE_S` in which the caller is confirmed; `POST /pay` only pays such a member (`NOT_FOUND` otherwise), amount `1..MAX_STAKE_UNITS` else `BAD_STAKE`, balance check → `INSUFFICIENT_FUNDS`.
- **identity-huddle-7 (clarifications).** Beyond §13's questions the drafts service maps `PARTICIPANTS_UNRESOLVED` → "Who's in?", `BAD_SIDES` → `{id:"sides", text:"Who is against you?", kind:"multi"}` (answer = names on side B; others side A, all become participants if none were explicit), and a missing-stake `BAD_STAKE` → "Stake each?". Any other engine error triggers one recompile with `CompileRequest.errors` + `rejected_yaml`; still failing ⇒ `status: "invalid"`. PATCH applies chips at the YAML-surface level on `toYaml(program)` and re-runs `canonicalizeDraft` + `validateProgram` (no LLM); chips sent before a program exists are kept and applied after the next compile. Only the draft creator compiles/patches; the ElevenLabs tool webhook acts as the draft creator (or the huddle creator for a new draft).
- **identity-huddle-8 (create_bet hand-off).** `POST /bets` lives in the bets module; it should call `identityHuddleServices(ctx).createBet(user, draft_id)` → `{bet, nonce, draft, program, acceptance_audio_hash, judges, sign}` (tx kind `create_bet`, meta `{draft_id, bet, nonce, program_hash}`) and wrap it in a BetView. Nonce = random 63-bit. Requires `status: ready`, caller = draft creator, kind ≠ market and every counterparty's acceptance for the current program_hash (`NOT_ACCEPTED`). `h_0` = sha256 of the latest dictation WAV, or zero when the latest input was typed.
- **bet-lifecycle-1 (bet record seam).** The lifecycle (`packages/backend/src/lifecycle/`) resolves a bet from the `bets` mirror, then `world_bets`, then the draft whose `bet.address` is the bet. Fields read: `program` (required; top level or `draft.program`), `labels`, `title`, `creator_user_id`, `huddle_id`, and `candidate_user_ids` (§8.5 candidates frozen at `POST /bets`; `candidates` accepted as an alias). Without `candidate_user_ids` the candidates are the participants then the enrolled confirmed huddle members in join order. Participant ↔ user mapping is by wallet. Whoever writes the `bets` mirror should persist `candidate_user_ids` at `POST /bets`. ## [compute-budget] §3.13 onchain compute budget (D-47)

Problem: at the old `MAX_EVAL_COST = 16384`, `run_rules` could exceed the 1.4M CU transaction limit ([anchor] 1, conformance-1). Fixed by optimizing first, then adjusting the constants. Every accepted buffer now provably fits with margin.

- **Interpreter optimizations (`crates/verdict-rules`, no semantic change; all 237 vectors and 2048 fuzz cases still match TS with `VERDICT_STRICT=1`).**
  - `[profile.release.package.verdict-rules] overflow-checks = false` (workspace `Cargo.toml`, interpreter only; the program keeps overflow checks). On SBF, checked `u64`/`i64` multiplication compiles to `__multi3` calls, and these dominated the old cost. The arithmetic is bounded by construction: coordinates ≤ 10⁴, products ≤ 2·10⁸, frames ≤ 36,000 + 1,024, Σw ≤ 8·2·64·12. Debug/test builds keep the checks, so the native suites still trap any overflow.
  - Records are read as fixed `[u8; 12]` arrays with one bounds check, and `present`/`bx` read only the bytes they need.
  - Velocity predicates read each record once (a ring of the last `VEL_K` centers). They compare `d² = dx² + dy²` against precomputed thresholds instead of taking `isqrt` per frame: `⌊isqrt(d²)·FPS/VEL_K⌋ ≥ p ⇔ d² ≥ ⌈p·VEL_K/FPS⌉²`, which is exact. `speed` uses a `[lo, hi)` range for `== / !=`.
  - Zone refs are prepared once per leaf (`geometry::Poly`: slope-normalized edges plus `polyBBox`). There is a bbox reject (provably the same result for even-odd), and line/zone refs take a fixed-geometry loop.
  - `center`, `feet`, `.opening`, `.interior` and `expand` use shifts and unsigned division. They give the same floor results because every coordinate is ≥ 0.
  - `and`/`or`/`not`/`before`/`rising` work on words and touch only `⌈|F|/64⌉` live words.
  - `holds` scans per segment instead of calling `frame_of` per position. `n_rule_frames` is O(segments).
  - Small decoder helpers are inlined.
  - Effect per frame (release, LiteSVM): `moving` 1,350 → 83 CU, `present` ≈ 280 → 27, `inside` zone 900 → 260 (8-point zig-zag, every edge crossed). Golden vectors: max `run_rules` 739,522 → 128,580 CU. Fuzz: 1,029,718 → 157,862 CU.
- **Constants (contract change; Engine + Chain + App mirror).**
  - `MAX_EVAL_COST` 16384 → 8192.
  - New `EVAL_COST_SETUP_FRAMES = 4` with `cost = (|F| + 4) × Σw`. Per-node work that doesn't scale with |F| (program decode ≈ 120–140 CU/node, signal set-up, zone preparation) was not charged at all before: a maximal program (8 legs × 2 × 63 nodes) at |F| = 1 cost up to ~900K CU at "cost 3,000".
  - `overlaps`/`inside` weigh 4 (was 2). `enters`/`leaves`/`touches` weigh 6 (was 4). With person anchors, `overlaps` runs two polygon tests per frame (≈ 345 CU/frame worst case). The other weights are unchanged. The velocity leaves needed no reweighting after the optimizations (≤ 56 CU per unit).
  - Paper-ball (§15.1) Σw 25 → 27: 299 buffer frames fit (was 655).
- **Proof obligation (`programs/verdict/tests/node_costs.rs`, release `.so` in LiteSVM).** `CU(run_rules) ≤ 40,000 + 60 × records + 120 × cost`. At the cap with a full payload (833 records) that is ≤ 1,073,020 CU (≤ 1.2M target). `run_rules` CU is linear in per-node set-up + per-node-per-frame work + per-record decode, so the tests check each term:
  - **Per frame.** Every node kind (39 leaf/operand shapes, 6 combinators with children subtracted, 6 rule kinds, 8-leg programs), with F in 1 segment and in 16, on adversarial data (8-point zig-zag zone, objects mostly present, stale sub-regions, toggling poses). Worst 86.2 CU per cost unit (`overlaps` zone with a person) against the bound 120.
  - **Set-up.** The largest decodable programs (8 count legs × 126 nodes of every leaf kind) at |F| = 1 and at 16 one-frame segments. Worst (CU − base − decode)/cost = 82.1.
  - **Decode.** 53.1 CU per record (bound 60).
  - **At-cap benchmarks** (`compute.rs`, no longer ignored): `state_heavy` (405 frames × Σw 20) 252,026 CU; `eight_legs` (386 frames, 4 segments) 210,231; `polygon` (451 frames, zig-zag zone, person) 541,765; `setup_heavy` (|F| = 5, 252 polygon nodes) 440,493; over-cap → panel in 69,449.
- Programs above the cap still go to reason 13 → panel, or SP1 (§9.4 #14, D-21). `windows.ts` still rejects plans with `cost > MAX_EVAL_COST`, and SP1/full-session evaluation (`maxCost = ∞`) is unchanged.

## [sp1-dropped] SP1 oversized-run path not built (D-9, spec §5.8.2 fallback (a))

The SP1 path (§9.4 #14, D-9/D-21/D-24) is **dropped for this build**; decisive-window execution onchain is the only pre-ruling path.

- There is no `sp1/` guest or host crate (the §1/§17 layout entries are aspirational).
- The backend never routes to SP1: nothing in lifecycle/seal calls `providers.sp1` or `verifySp1RunIx`. `SP1_PROVER=mock|network` is accepted by the config loader but **treated as off**: startup logs a warning ("SP1 path not implemented (D-9)"), every SP1 provider reports `enabled = false`, and `proveRun` throws `NotImplementedError`. `SP1_PROVER=network` still needs `ALLOW_SPEND=1` (spend guard).
- Oversized runs (windows that cannot reproduce the full-session result within `MAX_EVAL_FRAMES`/`MAX_EVAL_COST`, D-21 `window_unavailable`) always post a track_bin with flags bit3 and go to the panel (reason 13).
- `verify_sp1_run` stays a feature-gated, fail-closed stub per [anchor] 10: `Sp1Disabled` without feature `sp1`; with it, only the `mock-zk` test proof verifies.
- If the SP1 path is ever built: a guest that runs `verdict-rules` over the full track_bin with a large `W` and `maxCost = ∞`, a host using the Succinct network prover, sp1-solana's Groth16 verification behind feature `sp1` in `verify_sp1_run`, and `seal.ts` posting an SP1-only buffer (`tracks_finalized = 2`) instead of the bit3 buffer when `SP1_PROVER ≠ off`.

## [backend-audit] packages/backend + services/ fixes (audit round)

- **backend-audit-viewer (booth/exhibits/receipt/terms visibility).** `GET /bets/:id/booth`, `/exhibits/:eid`, `/receipt` and `/terms.yaml` now apply the `GET /bets/:id` rule before any lookup (`requireBetViewer`, lifecycle/betInfo.ts). Bets in the `bets` mirror or known through their draft: participants and *confirmed* huddle members. World bets: participants only. Bets the backend has no record of: the chain account's participants. Everyone else gets `NOT_FOUND`, the same as for an unknown bet. WS `booth` pushes go per viewer, with the same rule. `receiptRows()` stays ungated for internal callers.
- **backend-audit-witness (primary camera binding).** The creator, the only user who can PUT the calibration, must register the first camera. Until then, another member's camera gets `NO_CAMERA`. `start` orders the witness list with the creator's camera at index 0, followed by everyone else in registration order. A missing creator camera is `NO_CAMERA`, even if other cameras exist. Each user holds at most one witness per kind (`WRONG_STATE`). While the creator lacks a camera or audio witness, one slot for each stays reserved. A full list answers `HUDDLE_FULL` ("Huddle full"), not `WRONG_STATE`, so the app does not mistake it for "already registered". This reuses an existing code instead of adding a §12.8 code.
- **backend-audit-start (crash-safe start).** The live record is persisted as soon as `start` confirms, before any blob write or provider call. The SFX provider failing falls back to the bundled mock sound. If a bet is Live onchain with `beacon_slot > 0` but has no live record, it is adopted again: by `POST /start`, which rebuilds the record from the chain's `beacon_slot`/`beacon_hash`/`started_at` and never from a fresh SlotHashes read, and by the keeper. The keeper adopts only when the oracle is ours and every onchain witness is in our stored list.
- **backend-audit-calibration (calibration vs fund race).** PUT `/calibration` and POST `/fund` run under the same per-bet lock. PUT, and scene crop PUTs, answer `CALIBRATION_LOCKED` while an unexpired `fund` tx for the bet is pending. Every validated calibration is kept by hash (`scenes.history`). Once `bet.calibration_hash ≠ 0`, the onchain hash is the source of truth: fund signing, CAMERA_MISMATCH and perception sealing pin the scene back to `history[calibration_hash]`. Sealing fails rather than posting a calibration the chain does not have. The fund tx meta records the `calibration_hash` it signed.
- **backend-audit-prover (devnet needs real proofs).** `SOLANA_MODE=devnet` with `PROVER≠snarkjs` is a startup error, because all-zero mock proofs fail onchain Groth16 and every actor-bound bet would go to the panel. `snarkjs` (0.7.5, the version circuits/ pins) is a backend dependency, imported lazily on the first proof. `SnarkjsProver.close()` terminates the bn128 worker threads; app close calls it, and scripts and tests must call it too. If every proof of a bet fails, the backend logs at error level.
- **backend-audit-mint (devnet startup).** `ChainClient.init?()` is awaited in the app's `onReady`. On devnet without `USDC_MINT` it creates the test mint before any route reads `chain.mint`. If init fails (unfunded fee payer, RPC down), the error is logged and routes that need the mint answer `INTERNAL` with HTTP 503 instead of a raw 500. `POST /faucet` retries the mint creation.
- **backend-audit-errors (devnet error names).** `SendResult.error` on devnet is a name:
  - the Anchor `Error Code: X` log line, if present;
  - else `custom program error: 0x…` codes ≥ 6000, mapped through the IDL to the §9.6 name;
  - else a fixed runtime name (`BlockhashNotFound`, `InsufficientFunds`, `SignatureVerificationFailed`);
  - else `Custom(n)`, or `TransactionFailed` when nothing matches.

  Confirmed-but-failed transactions map `{InstructionError:[i,{Custom:n}]}` the same way. The raw message and logs go to the new optional `raw` and `logs` fields; they are logged and never shown to clients. If a send fails with "already processed", the backend looks up the signature status instead of reporting `TX_FAILED`.
- **backend-audit-tx (concurrent submits).** `POST /tx/:id/submit` runs its request checks per caller, then shares one in-flight send per tx. Confirm hooks run once, on the pending → confirmed transition, and a confirmed record is never overwritten.
- **backend-audit-delete (biometric media).** Accept WAVs are no longer stored; only their sha256 enters the acceptance leaf. `DELETE /enroll` also deletes any `acceptances/*_<user>.wav` written by older builds. On `Settled`/`Refunded` (§12.5 close-out), the bet's raw chunk bodies and scene crops are deleted. Its chunk hash records move to a per-bet `chunks_archive` record, which the receipt still reads. Exhibits and the sealed perception blob are kept. A Disputed bet only settles through the booth's `settle_panel`, so its exhibits already exist by then.
- **backend-audit-huddle (code guessing).** `POST /huddles/join` is limited to 10 attempts/min per user and 30/min per IP, plus 20 wrong codes/hour per user (`RATE_LIMITED`). A huddle holds at most 4 unconfirmed joiners. When a new joiner needs a slot, a joiner who has been unconfirmed for more than 10 minutes is dropped. `HUDDLE_FULL` comes only from that quota or from `MAX_HUDDLE` live members. Drafts (HTTP `requireDraft`, readback and question audio, WS `draft` pushes and huddle snapshots) are for confirmed members only. Unconfirmed joiners still get the `HuddleView`. The code TTL is unchanged (identity-huddle-6).
- **backend-audit-store (bounded persistence).** Collection writes are coalesced: a write happens at most once per 100 ms per collection, plus on `JsonStore.flush()`, app close and process exit. Writes still use temp + rename. Chunk records are bounded per witness. Non-final chunks are 500 ms–10 s long (final chunks may be shorter). `start_ms` and `index` must fall in the session window `time_limit + TAIL + LIVE_GRACE + 60 s` (at most window/500 ms + 2 chunks). Violations are 400 `WRONG_STATE`. Chunk POST/PUT is limited to 600 per user per minute. An hourly keeper task (`housekeeping`) prunes three kinds of record:
  - processed chain events older than 7 days;
  - settled txs older than 30 days, and pending txs whose blockhash expired more than a day ago;
  - challenges expired more than a day ago.
- **backend-audit-bodies (unauthenticated body limits).** `/v1/auth/*` bodies are limited to 16 KiB, `/v1/webhooks/elevenlabs/tool` to 1 MiB and `/v1/webhooks/quicknode` to 8 MiB; the global 48 MiB limit applies only to authenticated routes. Webhook secrets, headers and timestamp freshness are checked in `onRequest`, before the body is read. The QuickNode body is JSON-parsed only after the HMAC over the raw bytes verifies. `/v1/webhooks/*` is limited to 600 requests/min per IP.
- **backend-audit-media (signed chunk URLs; supersedes bet-lifecycle-8).** §6.0 `video_urls` are `GET {PUBLIC_URL}/v1/media/chunks/:bet/:witness/:index?exp=<unix ms>&sig=<hex>` with a 6 h TTL. The signature is `sig = HMAC-SHA256(K, "verdict/media/v1|bet|witness|index|exp")`, where `K = SHA-256("verdict/media-url-key" ‖ BIOMETRIC_KEY)`. No bearer token is needed; a bad or expired signature gets `UNAUTHORIZED`. The bearer route `GET /bets/:id/chunks/...` stays for the app.
- **backend-audit-faces (real-host face identity; §6.0/§6.1 extension).**
  - **Request and output fields.** The job request gets an optional `need_faces` (true iff any leg is actor-bound). On `entity: "person"` lines, the worker adds `face: {emb: 128 floats, L2-normalized, conf}` on frames with `floor(t_ms/100) % 3 == 0` where it finds a face inside the person box. It uses the same ArcFace-512 → fixed 512→128 projection as services/embedder, so enrolled templates match, and `model_hash` covers that model. `GET /jobs/:id` may add `frame: {width_px, height_px}`.
  - **Backend steps.** `faceObservations` uses the §6.2 dedup (frame = floor(t_ms/100), smallest t_ms per (frame, track)). Each sample yields `{frame, modality:'face', track_id, scores}`, and its quantized embedding is kept for the prover. `reidLinks` links a track that starts within 50 frames after another ended, when their `reid` vectors are at least 7000 bps apart in cosine. Per host, faces, then voices, then the re-ID links go into `fuseTimeline`. Host A's faces feed `planProofs`.
  - **Frame size.** §6.2 quantization uses the job's `frame` size, else the primary camera's chunk `width_px`/`height_px`, else the calibration camera.
  - **Missing field.** A worker without `face` support behaves as before: voice only.
- **backend-audit-nosana (Nosana adapter).** `PERCEPTION_PROVIDER=nosana` needs four settings: `ALLOW_SPEND=1`, `NOSANA_API_KEY`, `NOSANA_PERCEPTION_IMAGE` (pinned `…@sha256:<64 hex>`) and `NOSANA_MARKETS` (1–2 market addresses). `NOSANA_API_URL` defaults to `https://dashboard.k8s.prd.nos.ci/api`.
  - **Job definition.** Each of the two jobs is a `container/run` op with `gpu: true`, `required_vram: 24`, `cmd: python -m perception.oneshot`, and env `VERDICT_JOB` (base64 §6.0 body, fresh `job_nonce`) and `VERDICT_RESULT_URL`. The result URL is a signed `POST /v1/media/perception/:bet/:nonce` that stores `{model_hash, flags, frame?, detections_jsonl}`.
  - **API calls.** The adapter creates jobs with `POST {api}/jobs/create-with-credits {market, jobDefinition}` (Bearer API key) and polls `GET {api}/jobs/:address` until `COMPLETED`. `FAILED`/`STOPPED` or the 30-minute deadline fails the job.
  - **Host independence.** Both jobs must report different `node`s, else the pair fails.
  - **Hosts.** Host A = first COMPLETED (`runJobPair`, shared with `http`). `host = {provider:'nosana', job_id: <job address>, url: https://dashboard.nosana.com/jobs/<address>, market}`, `network: 'mainnet'`.
  - **Not yet verified.** These endpoint paths are the adapter's assumption about the Nosana credits API. Verify them against the current Nosana docs before the first paid run. Until then the `http` mode (services/perception in server mode on any GPU host) is the working real path.
- **backend-audit-services (services/perception, services/embedder).** Both are Python (FastAPI) and optional; neither is built by default or run by `npm test`. `scripts/test-services.sh` runs their CPU tests: generated fixture clips and stand-in models, no keys, no spend. Real-model tests are skipped without the pinned weights.
  - **Weights.** `weights.lock.json` pins each file by sha256, and the Docker builds run `fetch_weights.py --require-pinned`. The digests are still `null` (not fetched in this environment). Run `fetch_weights.py --pin` once and commit the digests before an image can be built. SAM 3 is gated on Hugging Face (needs `HF_TOKEN`), and its git ref is the required `SAM3_REF` build arg, recorded in `model_hash`.
  - **Golden output.** `services/perception/tests/golden/detections.jsonl` is checked by both the Python test and a backend test (`parseDetectionsJsonl` → engine `quantizeSession` → `faceObservations`).
- **backend-audit-pending-enroll (abandoned enrollments; contract addition `DELETE /enroll/pending`).** Pending enrollment templates (written by `POST /enroll/face` and `/enroll/voice`) are only made permanent by `POST /enroll/complete` with `consent: true`. New `DELETE /enroll/pending` → `{deleted: true}` drops them (idempotent; committed templates are untouched, that is `DELETE /enroll`). The app calls it when consent is switched off after a capture and when Enroll is left before Done; consent is now the first Enroll step. A pending enrollment idle for more than `PENDING_ENROLLMENT_TTL_MS` (24 h, from its last capture) is ignored on read and deleted by housekeeping (`pruneHotCollections` → `enrollments`).
